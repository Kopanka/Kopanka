# MAP-003 v1.4 — передача Android-розробці

## Вхід
- `prototype/android/app/src/main/assets/map/manifest.json`: schemaVersion 1, 62 assets.
- Всі PNG знаходяться у підпапках відносно manifest. Не виконувати Android density scaling.
- Редаговані SVG — у `source_svg/` і мають збігатися за іменами.
- Логічна тестова ділянка — `demo/map_32x32.json` (індексація cells[row][col]).

## Геометрія
- 512×512 логічних клітин; перший тест 32×32.
- Footprint 128×64 px при 1×, anchor (64,32) для ground.
- `worldX = (col-row)*64`, `worldY = (col+row)*32` (до панорамування і масштабу 1,2×).
- Для високих спрайтів використовувати anchor з manifest без автоматичного центровання PNG.
- Відображення: тільки видимі клітини плюс halo, високі спрайти сортувати за footprintY.

## Маски та рендер
- Річка N=1 E=2 S=4 W=8, маски 01..15; маску рахувати за глобальними сусідами (включно з межами чанків).
- Річкові PNG в v1.4 мають свідомий 1–кількапіксельний вихід штриха за ромб (залишаючись в 128×64 PNG) для перекриття ліній розриву. Не обрізати спрайт додатковим геометричним clip-ромбом.
- Береги 01..15 + 4 діагональні кути; маски кутів слід тестувати з реальною моделлю 8 сусідів.
- Порядок: ground → slope → water/coast → river → scenery → structure → fog. Туман недослідженого **повністю непрозорий** і перекриває високі об'єкти.
- Однаковий коефіцієнт 1,2× для всіх шарів; одна матриця трансформації.

## Перевірка в розробці
1. Виконати валідатор з PR #7 (`tools/validate_map_assets.py` з аргументом шлях manifest).
2. Побудувати карту із `demo/map_32x32.json`, перевірити чотири напрямки стиків річки та кутові береги при 1,2×.
3. Виміряти FPS/RAM на конкретному телефоні, перевірити туман після перезапуску, перекриття високих об'єктів і межі світу.
4. Не додавати героя, інтерфейс, транспорт, економіку; не міняти геометрію.

## Поточні обмеження
Попри локальну механічну перевірку річкових виходів, загальна seamless-якість і відповідність затвердженому живописному ескізу **не прийняті**. Потрібен художній перегляд і Android smoke test.
