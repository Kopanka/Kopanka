# MAP-005-ART-PROD — виробниче ТЗ для дизайну карти KOPANKA

Дата: 2026-11-27  
Відповідальний напрям: **Дизайн карти та ассети**  
Статус: **завдання передано; виробничі ассети ще не готові**  
Передача далі: **Розробка Android → Перевірка збірки → Координатор**

## 1. Мета

Перетворити погоджений користувачем **деталізований природний ізометричний стиль** KOPANKA на окремі **безшовні виробничі PNG-ассети** для справжньої карти 2,5D. Усунути візуальні проблеми Android 0.3.12: «земляні платформи», довгі прямі лінії на висотах, прямокутні береги, повторення однакових вершин. Природна печера — неправильний кам'яний вхід **без дверей та штучної арки**.

## 2. Затверджені незмінні параметри

- Світ: **512×512 логічних клітин**; на екрані лише видима ділянка.
- Ізометрична клітина **128×64 px** (до масштабування); базовий anchor **(64,32)**.
- Камера: **фіксований 1,2×**, без обертання, без зуму. Збереження позиції камери.
- Недосліджена місцевість прихована **суцільним графітовим туманом #3B3F42**; досліджена залишається відкритою. Колір fog НЕ вбудовувати в PNG.
- Тестовий висотний крок Android: **13 px/рівень** (технічне значення; остаточна художня висота не затверджена).
- Потрібні гори, долини, річки, море, острови, хвойний і листяний ліс, печера, шахта **в горах**, кар'єр **на рівнині**, поселення.
- Поточний етап **лише карта**: не додавати героя, інтерфейс, видобуток, транспорт, економіку, рекламу.

## 3. Вхідні матеріали

1. **Чинні рішення:** `main/docs/DECISIONS.md`; погоджений художній стиль зафіксований комітами `9eb87ef` та `5fae803`.
2. **Точна авторська демогеографія 32×32:** `docs/art/map-004-preview/demo_32x32.json` в арт-гілці, копія Android-демосцени; річка проходить від (5,3) до (24,20), 37 зв'язаних клітин.
3. **Арт-напрацювання:** `docs/MAP_004_ART_HANDOFF.md`, `docs/MAP_005_APPROVED_STYLE_IMPLEMENTATION.md`, `docs/MAP_005_SHORELINE_QA.md`, `docs/MAP_005_COMPOSITION_QA.md`.
4. **Генератори:** `docs/art/map-004-preview/generate.py`, `generate_shoreline_masks.py`, `render_authored_scene.py`. Поточні 27 SVG/PNG і 16 берегових масок — **технічні кандидати, не затверджені виробничі тайли**.
5. **Детальні художні кандидати:** 8 окремих PNG у локальному пакеті `MAP-005-передача-дизайн-перевірка.zip`, наданому в чаті. **Їхні бінарні файли ще не синхронізовані з GitHub**. Їх використовувати як художній референс, НЕ називати перевіреними безшовними 128×64 тайлами.
6. Фактичні скриншоти Android 0.3.11–0.3.12 та багрепорти в GitHub Issue #9.

## 4. Що саме створити

**A. Безшовна земля й висоти**
- Грунт/трава/камінь: повторювані базові ромби **128×64** без намальованих контурів по краях.
- Природні плавні схили **N/E/S/W**, внутрішні й зовнішні кути, діагональні стики й з'єднання висот.
- Скельні боковини видимих ребер із переходами для перепадів принаймні **1 та 2 тестові рівні**; правила розширення до 3–5.
- Не використовувати прямі сіро-коричневі смуги або суцільну вертикальну «стіну платформи» для природних пагорбів.

**B. Річки, море й узбережжя**
- Повний набір **16 4-бітних берегових масок** для пласкої суші: **N=1, E=2, S=4, W=8**, включно з маскою 00, яка є прозорою.
- Окремі берегові переходи на висотах: вода рівня 0 ↔ суша 1, 2; низькі схили, скелясті обриви, внутрішні й зовнішні кути.
- Витік, плавні повороти, розширення русла та природне **гирло в море**. Вода має бути без «трубних» сегментів, без решітки, без розривів.
- Піщані, трав'яні та кам'янисті береги з природними кривими, камінням і рослинністю, без регулярних прямокутних виступів.

**C. Природні об'єкти**
- Не менше **4–6 справді різних групових гірських хребтів** із нерівним силуетом; вершини не повторювати однаковими рядами. Врахувати Y-сортування.
- Групи хвойних і листяних дерев різної висоти, галявини й природні проміжки.
- **Природна печера:** нерівний темний отвір серед скель, осип каміння, мох; без дверей/балок. Шахта — окремий об'єкт у горах.
- Кар'єр на рівнині й невелике поселення — відповідно до погодженої стилістики, без ігрового інтерфейсу.

## 5. Технічний контракт передачі

Для **кожного** виробничого ассета:
- Окремий **RGBA PNG** з прозорим зовнішнім простором і **редагований оригінал** (SVG/PSD/інший придатний формат).
- Маніфест із `id`, `path`, `widthPx`, `heightPx`, `footprintCols`, `footprintRows`, `anchorX`, `anchorY`, `layer`, `sortFootY`, `adjacencyMask`, `variant`, `version`, `license`, `sha256`.
- Для базових клітин: **128×64 px, anchor (64,32)**. Для дерев, печери, гір та висотних боковин — природний розмір PNG і точна **опора на землі**, з документованим footprint та сортованою глибиною.
- Для кожного краю/кута — таблиця **правил стикування**, сумісність висот і шарів, альфа без чорних рамок/просвітів.
- Надавати **реальні файли**, а не лише один гарний концепт або загальне зображення світу.

## 6. Контрольна сцена і критерії приймання

Зібрати **одну авторську сцену 32×32** із окремих ассетів відповідно до `demo_32x32.json`: гірські хребти → природні долини → суцільна річка → море/острів, обидва типи лісу, печера, шахта, кар'єр, поселення.

Перевірити:
1. При **1,2×** не видно ромбічної сітки, чорних щілин, довгих прямих смуг на схилах, повторюваних гірських піків.
2. Вода, берег, кути й висоти стикуються у всіх 16 варіантах і на межі чанків.
3. Високі об'єкти мають правильну опору, Y-сортування та повністю приховуються туманом на невідкритих клітинах.
4. Узбережжя й річки природні, без прямокутних платформ, труб і розривів.
5. Географія демосцени не змінена довільно; жодної механіки поза картою.
6. Зробити **цілісне зображення сцени**, не лише аркуш розрізнених ассетів, з можливістю оцінити якість саме в контексті гри.

**Статус «дизайн готовий»** ставити лише коли є PNG, джерела, manifest, таблиця стиків, контрольна сцена та звіт перевірки. Затвердження власником художнього стилю **не дорівнює** затвердженню виробничих тайлів.

## 7. Формат результату для Android-розробника

Повернути: гілку/коміт із конкретними файлами або підписаний ZIP із фактичною доступністю, перелік ассетів і SHA256, маніфест, правила стикування/шарів/висот, контрольні скриншоти, звіт PASS/FAIL, відомі обмеження. Android інтегрує **саме цю версію**, збирає одну тестову APK; перевірка повертає реальні дефекти з пристрою. Не merge draft PR #10 до приймання.

**Залежність:** художні height-aware переходи й справді безшовні стики мають бути готові раніше за фінальне Android приймання.
