# MAP-005: підготовка Android до приймання погоджених макро-ассетів

Дата: 2026-11-27. Статус: **вхідний пакувальник готовий, фізичні PNG у GitHub ще відсутні**.

## Мета
Безпечно підготувати Android до отримання 8 оригінальних стилістично погоджених PNG KOPANKA, не перезаписати існуючі робочі 128×64 тайли та не видати макрооб'єкти за безшовний ландшафт.

## Вхідні матеріали
- Головне рішення: `main/docs/DECISIONS.md`, стиль погоджено, лише карта, геометрія 512×512, 128×64, anchor(64,32), zoom1.2, graphite fog #3B3F42.
- Арт-гілка: `art/map-004-height-aware-preview`, `docs/MAP_005_DESIGN_PRODUCTION_TASK.md`, `docs/art/map-005-intake/README.md`.
- Локальний ZIP `KOPANKA_MAP005_art_handoff.zip` з 8 RGBA PNG, manifest і SHA256. На момент цього звіту ZIP перебуває в робочому чаті, **не у GitHub**.
- Поточна Android карта: `0.3.12-riverbank-grading`, versionCode 16. Demo 32×32, модель світу 512×512.

## Створені файли й тести
1. `tools/stage_map005_macros.py` — читає й перевіряє ZIP, sha256/png/alpha, bounds, footprint/anchor; при явному запуску додає 8 файлів до `app/src/main/assets/map/map005_macro/` і нові унікальні ідентифікатори `map005_*` до каталогу. Класифікує як `scenery`, а не `ground`; створює окремий `map005_macro_staging_report.json`. **Не вмикає відображення цих PNG.**
2. `tools/test_map005_staging.py` — в тимчасовій папці створює 8 невеликих RGBA тестових PNG, переносить їх скриптом у копію маніфесту, перевіряє кількість, префікси, непорушність існуючих ground assets, статус відображення `false`, відхилення пакета, що помилково позначено як production-ready.
3. `.github/workflows/prototype-android.yml` — окремий тест приймання MAP-005 перед побудовою APK; тестові PNG синтетичні, не підміняють реальну графіку.

## Приймання та залежності
- **Технічне приймання**: GitHub Actions має показати PASS для `Validate MAP-005 staged PNG intake...` та PASS для компіляції Android з поточним маніфестом.
- **Передача дизайну**: потрібне фізичне додавання ZIP у `art/map-004-height-aware-preview/docs/art/map-005-intake/`, перевірка workflow `map005-art-intake.yml`.
- **Арт-приймання ще НЕ виконано**: 8 PNG — окремі 2×2 / 3×2 / 3×3 великі сцени; їхні natural cliff/shore seams та оклюзія на Android не перевірені. Повний набір height-aware 16 shoreline masks і природні похилі переходи залишаються відкритими.
- Тільки після арт QA інтегрувати **вибрані** об'єкти в рендер, не повторюючи геометричні артефакти 0.3.12. Один APK для фізичного тесту; **draft PR #10 поки не зливати**.

## Вплив на поточний APK
**Жодних змін зовнішнього вигляду чи номера версії 0.3.12 не зроблено.** Додавання неактивного скрипта і CI-тестів не є новою ігровою версією. Не пропонувати власнику повторно встановлювати той самий APK як результат художнього оновлення.

## Відкриті питання
Як фактично передати великий бінарний ZIP до GitHub (джерело створено в чаті, а доступний GitHub-конектор приймає лише текст/малий API-вміст), і хто робить останній художній seamless/height QA. Потреба завантаження файлу — єдина наступна зовнішня дія, перш ніж Android зможе зібрати кандидата з реальними погодженими PNG.
