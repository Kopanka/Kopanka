# MAP-003 — контракт отримання PNG-ассетів (підготовка Android)

Статус: **технічна підготовка, не приймання художніх матеріалів**. Рішення координатора MAP-001 у `main/docs/DECISIONS.md` ще очікується. Реальних PNG та затвердженого fog-art немає.

## Що вже працює
- MAP-002A, draft PR #5: камера 1.2×, 512×512, збереження досліджених клітин, тестове відкриття.
- `MapAssetCatalog.java` — окремий неактивований клас. Може прочитати `app/src/main/assets/map/manifest.json`, перевірити обов'язкові поля, унікальність ID, локальні безпечні PNG-шляхи, розміри, anchors, тип ground (128×64, 64×32) і декодувати одну картинку без auto density scaling.

**Важливо:** `MapSurface` навмисне ще не використовує `MapAssetCatalog`. Тому жодної заміни тестового рендера до передачі ассетів не сталося. У гілці немає зображень і немає змін APK `versionCode`.

## Формат файлів від артдиректора
Папка: `prototype/android/app/src/main/assets/map/`. У ній `manifest.json` і PNG за відносними шляхами без `../`.

Приклад **структури**, не затвердженого пакета:

```json
{
  "schemaVersion": 1,
  "assets": [
    {
      "id": "ground_grass_01",
      "path": "ground/grass_01.png",
      "widthPx": 128,
      "heightPx": 64,
      "footprintCols": 1,
      "footprintRows": 1,
      "anchorX": 64,
      "anchorY": 32,
      "layer": "ground",
      "sortFootY": 32,
      "adjacencyMask": "",
      "variant": "01",
      "version": "1.0",
      "license": "artist-confirmed"
    }
  ]
}
```

Усі обов'язкові ключі треба зберегти; для високих об'єктів width/height/anchor індивідуальні. Приклад тільки демонструє JSON: зображення і права на них має передати артдиректор.

## Наступні роботи після реальної передачі
1. Перевірити `manifest.json` та всі PNG на відповідність геометрії й ліцензіям.
2. Погодити точні набори масок берегів, річок, перехідних шарів, Y-sort, прозорі поля спрайтів і padding/bleed.
3. Підключити завантаження і кеш Bitmap до `MapSurface` **окремим кодовим комітом**; під час рендера лише видимі cells плюс halo, без повного 512×512 циклу.
4. Не розкривати приховану географію через PNG: рендер незвіданого — opaque fog; fog має перекривати високі об'єкти.
5. Оновити `versionCode` і зібрати `com.kopanka.maptest.stable` зі сталим лише тестовим підписом.
6. Протестувати на фізичному Android: геометрія/шви, 4 сторони і кути, фіксований масштаб, збереження туману, FPS/RAM (модель телефона та роздільність), стійкість після перезапуску.

## Заборони поточного етапу
Не створювати героя, меню, транспорт, економіку, рекламу; не малювати весь світ як один гігантський PNG; не зливати PR і не оголошувати MAP-003 «готово» без фактичних ассетів та Android-приймання.

## Залежності
- Координатор: офіційно затвердити MAP-001 у `docs/DECISIONS.md`.
- Артдиректор: передати PNG + вихідники + manifest + права використання; Issue #6.
- Android: після передачі — інтеграція й тест на телефоні.
